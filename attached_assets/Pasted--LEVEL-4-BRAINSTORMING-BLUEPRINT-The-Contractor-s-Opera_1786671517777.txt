## BAGIAN 1: AI MULTICLAW — ARSITEKTUR LENGKAP
### *Orchestrator + Gate + 7 Spesialis + Akses Langsung*

---

### 📐 PRINSIP DESAIN

```text
USER TIDAK PERNAH "BICARA DENGAN ROBOT".
USER MERASA SEDANG RAPAT DIREKSI DENGAN TIM AHLI.

TAPI:
- Jika user bingung harus tanya siapa → ORCHESTRATOR yang arahkan.
- Jika user sudah tahu butuh siapa → Langsung masuk ke SPESIALIS.
```

### 🎯 AI ORCHESTRATOR (Sekretaris Direksi)

**Nama:** "SI BOS" (atau nama brand Anda)

**Fungsi Orchestrator:**

```text
1. MENERIMA kasus dari user.
2. MENGANALISIS: Kasus ini butuh berapa spesialis?
3. MENGIRIM ke 1-3 spesialis secara paralel.
4. MENGUMPULKAN jawaban dari masing-masing spesialis.
5. MENYINTESIS jadi satu ACTION PLAN terpadu.
6. MEMPRESENTASIKAN ke user dalam format "Notulensi Rapat".
7. MEMBERIKAN opsi: "Mau ngobrol langsung sama SI PASAL 
   untuk detail hukumnya? Klik di sini."
```

**Contoh Alur:**

```text
USER: "Bos, PPK nahan BAST gue udah 3 minggu. Subkon pondasi 
ngancam stop kerja. Kas gue tinggal Rp 80 juta tapi tagihan 
Rp 400 juta. Gue harus gimana?"

AI GATE: → Urgensi: KRITIS → Domain: Multi → Kirim ke Orchestrator

ORCHESTRATOR: → Analisis: Ini butuh 3 spesialis.
  → Kirim ke SI BERKAS (kenapa BAST ditahan?)
  → Kirim ke SI KAS (gimana bagi Rp 80 juta?)
  → Kirim ke SI LAPANGAN (gimana handle subkon marah?)

SI BERKAS menjawab: "Cek apakah dokumen lo zero-defect. 
Kemungkinan besar ada back-up data yang kurang. 
Gue buatkan checklist yang harus lo lengkapi besok."

SI KAS menjawab: "Rp 80 juta vs Rp 400 juta. 
Pakai Cash Triage. Kuadran Merah: gaji tukang aktif. 
Kuadran Kuning: subkon pondasi → kasih Token Payment 
Rp 15 juta + jadwal pasti. Sisanya tahan."

SI LAPANGAN menjawab: "Subkon pondasi itu kritis path. 
Kalau dia stop, seluruh proyek berhenti. Telepon dia 
malam ini. Jangan WA. Telepon. Bilang jujur, kasih 
Token Payment besok pagi, dan janji tanggal pasti. 
Gue buatkan script-nya."

ORCHESTRATOR → SYNTHESIZE:

┌─────────────────────────────────────────────────────┐
│ NOTULENSI RAPAT DIREKSI VIRTUAL                      │
│ Kasus: BAST ditahan + Subkon ancam + Kas kritis     │
│ Tanggal: 14 Agustus 2026                            │
├─────────────────────────────────────────────────────┤
│                                                     │
│ DIAGNOSIS:                                          │
│ Akar masalah: BAST ditahan karena berkas belum      │
│ zero-defect. Ini memicu domino effect ke kas dan    │
│ subkon.                                             │
│                                                     │
│ ACTION PLAN (Urutan Eksekusi):                      │
│                                                     │
│ HARI INI (sebelum jam 17.00):                       │
│ ☐ Telepon subkon pondasi. Jangan WA.               │
│   Script: [dari SI LAPANGAN]                        │
│ ☐ Transfer Token Payment Rp 15 juta.               │
│                                                     │
│ BESOK PAGI (sebelum jam 10.00):                     │
│ ☐ Cek Zero-Defect Checklist.                       │
│   Kemungkinan besar: back-up data volume kurang.    │
│   [Checklist dari SI BERKAS]                        │
│ ☐ Kirim WA ke PPK: "Apakah ada koreksi?"           │
│   Script: [dari SI BERKAS]                          │
│                                                     │
│ MINGGU INI:                                         │
│ ☐ Eksekusi Cash Triage Matrix.                      │
│   [Matriks dari SI KAS]                             │
│ ☐ Hitung Runway. Jika < 14 hari, aktifkan Buffer.  │
│                                                     │
```

```text
  "Surat sudah jadi, Bos. Kalau mau gue cross-check
```

## BAGIAN 2: RUANG SIMPAN + RUANG KELOLA + TOOLKIT
### *Elaborasi untuk Gustafta.my.id*

---

### 📐 PRINSIP INTEGRASI

Ketiga komponen ini bukan 3 aplikasi terpisah. Mereka adalah **satu organisme** dengan 3 fungsi:

```text
RUANG SIMPAN  =  GUDANG / BRANKAS
                  (Tempat menyimpan semua dokumen & data)

RUANG KELOLA  =  MEJA KERJA / COMMAND CENTER
                  (Tempat mengolah data jadi keputusan)

TOOLKIT       =  LACI ALAT
                  (Template & script yang dipakai saat eksekusi)

ALUR:
  User upload dokumen → masuk RUANG SIMPAN
  → RUANG KELOLA membaca & menganalisis
  → User eksekusi keputusan pakai TOOLKIT
  → Hasil eksekusi di-upload balik ke RUANG SIMPAN
  → Siklus berulang
```

---

**Fitur Cerdas yang Dielaborasi:**

| Fitur | Fungsi | Value untuk User |
|-------|--------|-----------------|
| **Auto-Tagging AI** | User upload foto BAST → AI otomatis baca tanggal, nilai, nomor kontrak → tag ke folder yang benar | Tidak perlu sorting manual |

| **Reminder Masa Berlaku** | Sistem ingatkan: "Jaminan Pelaksanaan Proyek X habis 15 hari lagi" | Tidak kena penalti karena lupa |
| **Version Control** | Jika ada revisi BAST, versi lama tidak hilang. Tersimpan sebagai history | Bukti jika ada sengketa |
| **Enkripsi & Backup** | Data terenkripsi, backup harian ke 2 lokasi berbeda | Anti hilang, anti bocor |

## BAGIAN 3: WORKROOM (Ruang Rapat Proyek)

---

### 📐 KONSEP

Setiap proyek di Gustafta.my.id punya **Workroom** sendiri. Ini adalah "Direksi Keet Digital" tempat user, AI, dan (opsional) tim manusia berkolaborasi.

**Isi Workroom per Proyek:**

```text
┌─────────────────────────────────────────────────────┐
│  🏗️ WORKROOM: Proyek Gedung Dinas Pendidikan         │
│                                                     │
│  TAB 1: OVERVIEW                                    │
│  → Health check, runway, status termin              │
│                                                     │
│  TAB 2: DOKUMEN (→ Ruang Simpan)                    │
│  → Semua berkas proyek ini                          │
│                                                     │
│  TAB 3: CHAT AI (→ Klinik Konsultasi)               │
│  → Riwayat semua konsultasi tentang proyek ini      │
│  → AI sudah punya konteks: "Proyek ini kas-nya      │
│    minus Rp 200 juta, BAST ditahan di Titik 3"      │
│                                                     │
│  TAB 4: TIM & TUGAS                                 │
│  → Siapa mandor, siapa admin, siapa subkon          │
│  → Tugas minggu ini (dari Friday Review)            │
│                                                     │
│  TAB 5: LOG & HISTORY                                 │
│  → Semua keputusan yang pernah diambil              │
│  → "14 Agu: Transfer Token Payment Rp 15 jt         │
│     ke Subkon Pondasi"                              │
│                                                     │
│  TAB 6: DOKUMEN ZERO-DEFECT                         │
│  → Checklist interaktif untuk termin selanjutnya    │
│  → Upload berkas → AI validasi kelengkapan          │
│                                                     │
└─────────────────────────────────────────────────────┘
```

**Keunggulan Workroom:**
- AI punya **memori per proyek**. Tidak perlu menjelaskan ulang dari nol setiap kali chat.
- Semua keputusan tercatat. Jika ada sengketa 6 bulan kemudian, user tinggal buka Log.
- Jika user punya admin atau mandor, mereka bisa di-invite ke Workroom dengan akses terbatas.

## BAGIAN 5: PRICING TIER
### *Berdasarkan Nilai Proyek & Kualifikasi Usaha*

---

### 📐 PRINSIP PRICING

```text
JANGAN JUAL "FITUR". JUAL "KETENANGAN".

Kontraktor tidak bayar untuk "AI chatbot".
Mereka bayar untuk: "Gue bisa tidur nyenyak karena 
kas gue aman, berkas gue rapi, dan kalau ada masalah 
gue punya tim ahli yang bisa gue tanya jam 11 malam."

Semakin besar proyek yang dipegang, semakin besar 
risiko yang dihadapi, semakin mahal "ketenangan" itu.
```

---

### 💰 STRUKTUR TIER
