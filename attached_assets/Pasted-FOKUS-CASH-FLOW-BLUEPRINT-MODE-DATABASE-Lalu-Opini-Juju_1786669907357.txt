🔍 CONTOH PERBEDAAN PERILAKU
Tanpa Blueprint Mode (AI umum):
User: "Termin gue macet."
AI: "Termin macet bisa karena banyak hal. Coba cek berkas Anda..." (generik, minta data ulang)
Dengan Blueprint Mode (Proyek A):
User: "Termin gue macet."
AI: "Bos, gue lihat di Pipeline Proyek A, Termin 2 lo ada di
Titik 3 (Verifikasi PPK), hari ke-12 — sudah masuk zona
waspada. Runway lo 23 hari, jadi masih ada napas, tapi
jangan didiamkan.
Aksi hari ini:
☐ Kirim follow-up ke PPK. [GENERATE SCRIPT]
☐ Cek Zero-Defect, pastikan nggak ada alasan buat nahan.
Mau gue buatkan script follow-upnya sekarang?"
Bedanya: AI kedua tahu data, tahu alat, tahu ritual, dan langsung kasih aksi. Itulah efek Blueprint Mode.

📌 CATATAN DEVELOPER
Workroom memory = chats.project_id. AI load riwayat chat proyek itu sebagai konteks.
Blueprint Mode aktif jika ada baris project_blueprints.status=active untuk proyek tersebut. Backend menyuntikkan [KONTEKS PROYEK] + [OVERLAY] ke prompt.
Quota gating baca quota_usage vs limit tier sebelum izinkan chat/draft/bedah.
Alert engine = cron harian yang hitung dari metrics_snapshots + documents (expired) + status termin.
Tier limit proyek: T1=1, T2=3, T3=10 → cek jumlah projects.status=active per user.
